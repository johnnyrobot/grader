## The three CI gates that block a release

These are unusually strict for an OSS v1. That's deliberate: **trust is the product.** A grading
tool that is occasionally unfair is worse than no grading tool.

**1. Quality gate — golden set**
~100 human-graded submissions across ≥4 assignment types. CI reports **QWK**, override-simulation,
and per-criterion disagreement per model/prompt version.
**Ship gate: QWK ≥ 0.70 (or parity with the human ceiling). A prompt/model change that drops QWK
by >0.03 does not ship.**

**2. Fairness gate — bias suite**
Style perturbations (informal tone, non-native phrasing, verbosity) applied to golden-set items
with content held constant. Score deltas must stay within threshold.
This directly implements arXiv 2603.18765, which found essay grading carries **significant bias for
every perturbation** (informal −1.9/10, non-native −1.35) that **survives explicit "ignore style"
instructions**. Prompt engineering alone does not fix this. Measure it or you are shipping it.

**3. Privacy gate — egress audit**
Capture all network traffic during a full grading batch. **Any packet to a non-allowlisted host, or
any allowlisted request containing student tokens, fails the build.**
Allowlist: the user's Canvas · model CDN · doi.org/Crossref/Semantic Scholar/OpenAlex · ddgs ·
citation fetch targets. Nothing else.

## Distribution (decided)

**Never bundle weights.** macOS App Store's limit is 200 GB (the 4 GB limit is iOS) so bundling is
*legal* — but it makes every release re-notarize gigabytes and bloats Tauri updater artifacts. **Every**
comparable app (Ollama, LM Studio, Draw Things, Jan, Msty) downloads on first run. Apple DTS
explicitly recommends separating large resources; **Background Assets** gives 200 GB of Apple hosting
free with the developer membership.

**Direct distribution first** (notarized DMG + Homebrew cask) — it permits the Python engine process
and an Ollama sidecar without sandbox contortions. Mac App Store later requires the Draw Things
shape: in-process MLX inference, helpers signed with exactly `app-sandbox` + `inherit`.

## Rollout

Private alpha (dev + 1 instructor, local files) → private beta (3–5 instructors, real Canvas
courses, weekly feedback) → **public v1.0 on GitHub**.

Post-launch: publish the calibration-results write-up. Showing real QWK numbers against a human
ceiling is the credibility artifact that separates this from every "AI grader" that ships vibes.

## ▶ Build sequence

**1. The three gates, as CI jobs** (`.github/workflows/gates.yml`):
```bash
uv run python engine/gates/quality.py   # golden set -> QWK; fail if <0.70 or regressed >0.03
uv run python engine/gates/bias.py      # style perturbations; fail if score delta > threshold
uv run python engine/gates/egress.py    # capture traffic during a batch; fail on any stray packet
```
The egress gate is the load-bearing one — it's the difference between *claiming* privacy and
*proving* it. Run a full grading batch under `tcpdump`/proxy capture and assert the allowlist.

**2. Perf on the FLOOR, not the dev box.** Test on a 16 GB machine (or cap memory). The 64 GB M2 Max
hid a 41 GB model from us once already (see P0).

**3. Sign, notarize, staple, update.**
```bash
# Prereqs: Apple Developer ID cert in keychain, notarytool credentials stored
xcrun notarytool store-credentials grader --apple-id you@email.com --password APP_SPECIFIC_PW --team-id TEAMID

# If the signing doctor blocks, generate a secret-free local repair runbook
uv run python scripts/signing_doctor.py --print-repair-runbook > signing-repair-runbook.md

# Fail closed if the release tag and app/runtime metadata drift
uv run python scripts/release_version_guard.py --tag v0.1.1 --out artifacts/release-evidence/release-version.json

# Dry-run the N+1 version move. Use --apply only in the release-prep commit.
uv run python scripts/bump_release_version.py --target-version 0.1.1 --allow-same --out artifacts/release-evidence/version-bump-plan.json

# Read-only publication preflight before creating/pushing the N+1 tag.
# It verifies the private source repo and public assets repo; Apple signing stays local.
uv run python scripts/github_release_preflight.py --candidate-tag v0.1.1 --out artifacts/release-evidence/github-release-preflight-current.json

# Build + sign + notarize + DMG in one command
./scripts/sign_and_notarize.sh --dmg

# Generate signed Tauri updater manifest. Encrypted keys need the password env var.
uv run python scripts/updater_key_doctor.py --print-private-runbook > updater-key-private-runbook.md
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD='<updater-key-password>'
uv run python scripts/generate_appcast.py --app Grader.app --version 0.1.1 --signing-key key.pem --output latest.json
uv run python scripts/updater_evidence.py --manifest latest.json --artifact Grader.app.tar.gz
uv run python scripts/updater_channel_preflight.py --current-version 0.1.0  # after publishing 0.1.1 to test installed 0.1.0 -> 0.1.1
uv run python scripts/release_readiness.py --profile public_beta --expected-version 0.1.1 --release-version-artifact artifacts/release-evidence/release-version.json --github-release-artifact artifacts/release-evidence/github-release-preflight-current.json --updater-artifact artifacts/release-evidence/updater-current.json --updater-channel-artifact artifacts/release-evidence/updater-channel-current.json --updater-key-artifact artifacts/release-evidence/updater-key-current.json --clean-machine-artifact artifacts/release-evidence/clean-machine.json

# Push a tag for clean source verification; signing and publication remain local:
git tag v0.1.1 && git push origin v0.1.1
```
Weights live **outside** the bundle (first-run download) — that's what keeps notarization fast and
update deltas small. Tauri's built-in updater handles updates via a signed `latest.json` manifest.
`scripts/generate_appcast.py` intentionally fails without `--signing-key`; encrypted updater keys
also require `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` in non-interactive release runs, or a named macOS
Keychain item passed with
`--password-keychain-service TAURI_SIGNING_PRIVATE_KEY_PASSWORD --password-keychain-account grader-updater`.
Use `scripts/updater_key_doctor.py --print-private-runbook` for secret-free local setup commands.
Use `--allow-unsigned` only for local smoke fixtures, never for release evidence.
`scripts/release_readiness.py` records artifact path/mtime/SHA-256 metadata and rejects PASS updater
or clean-machine artifacts whose recorded version does not match the release being evaluated.
`scripts/release_version_guard.py` also runs in the GitHub release workflow so tags cannot publish
an app bundle or update-check path whose Tauri/Rust/frontend/Python/launcher/mock metadata still
reports a different version. Use `scripts/bump_release_version.py --target-version <N+1>` as a dry
run, then `--apply` only in the deliberate N+1 release-prep commit.
The GitHub workflow verifies release source tests/builds but does not sign or publish. Apple signing
and notarization use the existing local Keychain identity/profile. `scripts/github_release_preflight.py`
checks candidate version drift, private/public repository access, release-source checks, updater
endpoint, and existing tag/release state without writing to GitHub.
`scripts/publish_local_release.py --apply` uploads only the verified DMG, signed `.app.tar.gz`, signed manifest,
checksums, and provenance.
`scripts/updater_channel_preflight.py` validates that the live GitHub release channel advertises a
newer signed `Grader.app.tar.gz` before a clean-machine tester starts the in-app update path; it does not
replace that behavioral evidence.

## Positioning (from the research)

Teachers and students **accept AI narrative feedback but distrust AI numerical scores**
(arXiv 2606.12422). So: the teacher always approves the number; AI-drafted comments can be
lighter-touch. Position Grader as a **formative drafting assistant**, never an autonomous summative
grader. That is both honest and what the evidence supports.
