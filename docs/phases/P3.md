## Four gotchas — all discovered the hard way, all will bite you

1. **`bulk-update` is ASYNCHRONOUS.** `POST .../submissions/update_grades` returns a **Progress**
   object, *not* grades. They are **not live** when the call returns (~4s to `completed`). If Grader
   reports success on the POST alone, it will tell a teacher a batch posted when it hasn't.
   **Poll `/progress/:id`.**
2. **canvas-pp-cli's read envelope is `{meta, results}`** — *not* `{data}`. Mutations use
   `{action, resource, success, data, partial_failure}`. Parsing the wrong key returns **zero rows,
   silently.** (This fooled me once; it will fool the importer.)
3. **Submission attachments must be uploaded as the STUDENT** (`?as_user_id=:sid`). A teacher POSTing
   to `/users/:sid/files` gets **403** even for the built-in Test Student. Needs `become_user`
   permission. *Comment* attachments are teacher-scoped and need no masquerade.
4. **Canvas returns HTML unless you send `Accept: application/json`.**

Plus: **Canvas Free-for-Teacher is permanently discontinued** (killed after the 2026 breach). Any
plan assuming a free Canvas signup is out of date.

## Build

- Wrap `canvas-pp-cli --agent` (JSON envelopes) or embed `canvas-pp-mcp`. The binary is at
  `/Users/johnnyrobot/code/canvas-pp-cli` — full Canvas REST surface (~1,180 commands), already audited
  (`docs/research/06-canvas-pp-cli-audit.md`).
- **Build the attachment downloader yourself** — the CLI returns attachment *URLs*, not bytes.
  Authenticated GET with the bearer token. This is the one real gap in the CLI.
- Import: `to-grade` (cross-course ungraded queue) → `submissions index/show` → download attachments
  → parse → enqueue. Report partial failures per-student, retryable.
- Post-back: approved items only. `submissions update` (single) / `bulk-update` (batch, **poll the
  Progress**). Annotated files upload via the 3-step flow, referenced as `comment[file_ids][]`.
- Offline mode: imported batches remain fully gradable with no network; posts queue.

## Invariant

**Nothing posts without explicit teacher approval.** A `GradeRecord` cannot enter `posted` without
`teacher_final.approved_at`. Enforce it in the data layer, not just the UI.

```python

```
**Assert on `results`, not `data`** (gotcha #2). Surface `partial_failure` per item.

**2. The attachment downloader** — the one real gap in the CLI. It returns URLs, not bytes:
```python
# submissions show -> attachments[].url ; GET it with the bearer token
def download_attachment(url: str, dest: Path) -> Path
```
Test against course 106: the Test Student's submission has a real `.md` attachment.

**3. Import job:** `to-grade` → `submissions index --include rubric_assessment,submission_comments`
→ download attachments → Docling parse → enqueue. Per-student partial failures, retryable.

**4. Post-back:** approved items only.
- Single: `submissions update` with `posted_grade` + `rubric_assessment` + `comment`.
- Batch: `submissions bulk-update` → **poll `/progress/:id` to `completed`** (gotcha #1) before
  reporting success. Test with the 6-student cohort.
- Annotated files: 3-step upload → `comment[file_ids][]`.

**5. Offline queue:** imported batches grade with no network; posts queue until connectivity.
